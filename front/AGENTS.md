# front — Веб-клиент (SPA)

## Overview
Одностраничный веб-клиент к REST API ядра: `index.html` (HTML + CSS + JS),
раздаётся отдельным сервисом (nginx). Отдельный деплой и образ — ядро его не знает.

## Boundaries
- **Делает:** вкладки Проекты / Воркстейшны / Сессии / Персонал / Чат; создание
  проектов, открытие/закрытие сессий на воркстейшнах, просмотр воркстейшнов
  и персонала; отправка сообщений, отображение дерева сообщений, артефакты,
  опрос для ответов реактивных агентов; вход через SSO.
- **Не делает:** никакой бизнес-логики — всё через REST API ядра (`/users`,
  `/chats`, `/messages`, `/agent-sets`, `/workstations`, `/projects`). Не хранит
  состояние на сервере, не авторизует (только шлёт токен ядру). Управление
  воркстейшнами (создание/удаление) из интерфейса недоступно — станции
  поднимает админ внешне.

## Tech Stack
- `index.html` — весь клиент: разметка, стили, vanilla JS (fetch), без сборщика.
- nginx — раздача статики (`front/Dockerfile`).

## Architecture
```
front/
├── AGENTS.md            # этот уровень
├── index.html           # SPA (весь клиент)
└── Dockerfile           # nginx: раздаёт index.html
```

## Patterns
- Все запросы — `fetch` к `API_BASE` (адрес ядра, `http://api.localhost` для
  стенда). Аутентификация — `Authorization: Bearer <token>`.
- Сессии = корневые чаты (`POST /chats`); ответы агентов приходят асинхронно —
  клиент опрашивает `GET /chats/:id` и перерисовывает при изменении.
- Вход: переход на `/auth/login` ядра, после входа токен возвращается клиенту
  (см. историю перехода с cookie на Bearer) и хранится в `localStorage`.
- При 401 клиент показывает кнопку «Войти через SSO».

## Verification
- Локально: раздать `index.html` (например `make run-front`) и открыть страницу —
  грузится без ошибок консоли; API-запросы уходят на ядро.
- Стенд: `curl http://dev.localhost/` возвращает `index.html`; ядро
  (`api.localhost`) отвечает на `GET /users` с `Origin: http://dev.localhost`
  CORS-заголовками.
- Тесты контента интерфейса (воркстейшны/персонал только показываются, есть
  логин-ссылка) живут здесь, а не в ядре.

## Dependencies
- Ядро aga (`main/`) — REST API + `/auth/*`.
- nginx (образ), стенд — `infra/k8s/`.
