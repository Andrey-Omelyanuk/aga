# E2E-тесты aga

## Зачем и сколько
Логику ядра и фронта проверяют юнит-тесты: `make test` (~240 тестов в
`main/`, SQLite в памяти, моки HTTP/LLM) и `vitest` во `front/` (~75 тестов
моделей и компонентов). Они быстрые и детерминированные, поэтому основная
проверка — в них.

E2E нужен для того, что юнит-тесты не видят: стыков между процессами и
внешними системами. Это настоящий Keycloak, Centrifugo, контейнеры или поды
воркстейшнов, git по SSH, отдельный процесс `aga agent` и LLM по HTTP.
Поэтому e2e намеренно маленький: по одному сценарию на каждый стык, без
повторной проверки бизнес-правил.

Правило: если поведение можно проверить юнит-тестом, оно проверяется
юнит-тестом. В e2e остаётся только то, что ломается на стыке.

## Наборы
| Команда | Где | Что проверяет | Время |
|---|---|---|---|
| `make dev-verify` | dev-стенд (docker compose) | стенд поднят: сервисы, прокси, SSO | ~1 мин |
| `make dev-e2e` | dev-стенд | рабочий цикл: SSO → воркстейшн → агент → `ask_human` | 3–10 мин |
| `make k8s-verify` | minikube | то, что есть только в k8s: поды, PVC, изоляция | ~10 мин |

Порядок запуска на dev-стенде:

```bash
make init        # один раз: .env и main/config/roles.yaml
make dev-up      # поднять стенд
make dev-verify  # стенд жив
make dev-e2e     # пересобирает core/agent/ws-1/ws-2, сеет БД, гоняет сценарии
```

`make dev-e2e` сам сбрасывает БД сидом (`aga seed`), поэтому повторный
прогон стартует с тех же фикстур.

## dev-e2e: сценарии
Скрипт — `infra/dev-e2e.sh`. Каждый шаг печатает `==> N. ...`; при падении —
`FAIL: <что не так>`.

### 1. SSO
- Аноним получает `401`.
- Токены, выданные Keycloak для `alice` (participant) и `bob` (admin),
  принимаются ядром.

Почему e2e: юнит-тесты проверяют JWT на сгенерированных ключах
(`auth.rs`). Здесь проверяется, что ядро действительно забирает JWKS у
Keycloak стенда и что realm (`keycloak-realm.json`) совпадает с сидом по
`sso_subject`.

### 2. Жизненный цикл воркстейшна
- Сид даёт проект `mobx-model-ui` и станцию с открытой сессией.
- Владелец (alice) закрывает сессию, админ (bob) отпускает станцию.
- Новая сессия с проектом разворачивает git-клон: в `/work/project`
  появляется `README.md` (проверяется через API дерева файлов).

Почему e2e: правила сессий (одна на станцию, закрывает владелец, release
только у админа) покрыты в `chat.rs` и `server.rs`. E2E проверяет то, чего
там нет: `docker exec` в контейнер станции, SSH-ключ и настоящий `git clone`.

### 3. Агент отвечает через живую LLM
- bob пишет `@alice что за проект?` в чат сессии.
- Агент `ui`, привязанный к alice, отвечает от её имени (`origin=agent`);
  у ответа есть артефакт, и это не `Ошибка: ...`.

Цепочка целиком: HTTP-ядро → публикация в Centrifugo → SSE-подписка
`aga agent` → маршрутизация → LLM (ollama, `qwen3:0.6b`) → команды в
воркстейшне → ответ в чат.

Почему e2e: в юнит-тестах рантайм получает события напрямую, без
Centrifugo, а формат кадров SSE задан в тесте вручную. Этот сценарий поймал
две ошибки, которые юнит-тесты пропускали: Centrifugo не принимает `?token=`
(connect-запрос передаётся в `cf_connect`), а канал в кадре v6 лежит рядом с
`pub`, а не внутри него. Из-за второй ошибки рантайм молча отбрасывал все
события.

Качество ответа не проверяется: маленькая модель недетерминирована, важно
только, что цикл прошёл.

### 4. human-in-the-loop (`ask_human`)
- Проект переключается на набор из одного агента с детерминированной
  mock-LLM. Это контейнер `node:22` в сети стенда: первый ответ — вызов
  `ask_human`, дальше — финал.
- Вопрос агента появляется в чате текстом; служебных строк (`Request ID`,
  `WAITING_FOR_HUMAN`) нет.
- bob, не привязанный ни к одному агенту, отвечает с `parent_id` на вопрос,
  и агент возобновляется до финального ответа от имени alice.

Почему e2e: парковку и возобновление задачи проверяют `agent.rs` и
`runtime.rs`. Здесь проверяется, что ответ человека проходит тот же путь
через Centrifugo и отдельный процесс. Mock нужен, потому что маленькая LLM
не вызывает `ask_human` надёжно.

## k8s-verify: только то, что есть в кластере
Скрипт — `infra/k8s/verify.sh`. LLM не нужен.

- Ядро и фронт — деплойменты в кластере, API и SPA отвечают через
  port-forward, CORS пускает origin фронта.
- Keycloak в кластере: страница входа доступна извне, `/auth/login`
  редиректит на неё; невалидный токен получает `401`.
- Воркстейшн — отдельный под `ws-<id>` с копией проекта, своим Docker и своей
  веткой; у пода нет доступа к API кластера.
- Команды агента идут из пода ядра в под станции (`kubectl exec`).
- Удаление станции удаляет под; данные ядра переживают рестарт (PVC).

Почему отдельно от dev-e2e: dev-стенд работает через `docker exec`, а
kubectl-бэкенд, RBAC и PVC существуют только в кластере.

## Что e2e сознательно не проверяет
- **Бизнес-правила чата, наборов, LLM-подключений, скиллов и сокращений** —
  это юнит-тесты `server.rs`, `chat.rs`, `trace.rs`.
- **UI в браузере.** Браузерного e2e (Playwright и т. п.) нет: компоненты и
  модели покрыты `vitest` и Storybook, а `dev-verify` проверяет только, что
  SPA раздаётся. Ручная проверка — `dev.localhost` под alice/bob.
- **Качество ответов LLM.** Это не свойство платформы.
- **MCP-серверы.** Протокол и вызовы покрыты `mcp.rs`; сквозного сценария нет.

## Известные пробелы
Кандидаты в e2e, если будут ломаться на практике:
- **Песочница территории.** Юнит-тест `scope.rs` проверяет только сборку
  команды. Что запись вне своей папки падает в настоящем mount namespace
  станции, автоматически не проверено. Для сценария нужен набор с дочерним
  агентом и mock-LLM, которая пишет вне территории.
- **Вход через браузер** (`/auth/login` → Keycloak → `/auth/callback` →
  cookie). Проверен только редирект на Keycloak, сам callback — нет.
- **Внешняя зависимость.** Сценарии 2–3 клонируют
  `git@github.com:Andrey-Omelyanuk/mobx-model-ui.git`. Без сети или без
  `AGA_SSH_PRIVATE_KEY` с доступом к репозиторию они падают.

## Если упало
- `FAIL: no agent reply` — смотри `docker logs aga-agent`. Цикл
  `подписка завершена, переподключение` означает, что рантайм не подключается
  к Centrifugo (смотри `docker logs aga-centrifugo`).
- Рантайм и ядро — один образ `aga-core:dev`. `make dev-e2e` пересоздаёт оба;
  при ручном запуске скрипта пересобери их сам, иначе рантайм останется
  старым.
- `FAIL: project code did not appear` — нет SSH-доступа к GitHub из станции
  (`AGA_SSH_PRIVATE_KEY` в `.env`).
