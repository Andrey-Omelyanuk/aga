Chat 
-------------------------------------------------------------------------------
Отдельный модуль где пользователи может обмениваться сообщениями в чатах.

## Chat
Внутри чата могут создаваться другие чаты. т.е. чаты могут образовывать дерево.
- id - int, pk
- root_id - fk, id = root_id для корня
- parent_id - fk, can be null
- level - глубина в дереве, 0 - это корень, нужен для ограничения вложенности
- title - 128 chars, can be null
- created_by_id - user создатель чата
- created_at - когда был создан чат
- updated_at - когда было последнее сообщение в чате (сообщения в дочерних не считаются)
- state - OPEN/CLOSED - по умолчанию OPEN
- result_id - can be null, сообщение только из этого чата, который считаеться итогом этого чата
                может устанавливаться только владельцем чата

Редактирование дерева чатов не предусмотренно.

## ChatUser
- id - int, pk
- name - char 128, not null
- is_super_user - bool, by default false - доступ ко всем чатам

## ChatParticipant
Если user есть в участниках, то он может "писать" в чат.
Создатель чата тоже тут. 
Доступы не распростроняються на родительский или дочерние чаты. Они требуют все отдельные доступы.
- id - int, pk
- chat_id
- chat_user_id

unique togather: chat_id - chat_user_id 

## ChatMessage
- id - int, pk
- chat_id - fk
- author_id - int, fk to chat user
- created_at - когда сообщение было сформированно и отправленно 
- last_message_id - какое сообщение было последним в чате, 
    когда пользователь начал формировать ответ, 
    полезно для агентов или пользователей которые долго думают над ответом
- response_to_id - на какое сообщение это ответ
- body - str

Cообщение может содержать "комманды":
- @UserName - указание на ChatUser
- #invite @UserName - создает доступ к текущему чату для UserName
- #kick @UserName - удаляет доступ
- #start <Title> - создание нового дочернего чата из текущего, 
    только создатель в него попадает, остальные могут быть приглашены явно отдельными сообщениями
- #end - закрытие текущего чата
Любой участник может вызвать #invite, #start
Владелец чата еще #kick и #end.
Если сообщение содержит комманду, оно не становиться каким то особенным, 
это все еще простое сообщение видимое всем,
просто на нее есть дополнительная реакция.
Редактирование сообщений не предусмотренно.


### Examples
Timeline:
User A create a chat.
A: hello, it's my first chat
A: let's #invite @B here
B: hi, whatsup?
A: #start
        A: there is a new chat
        A: I beleave user B have no access here
B: I'm starwing, need to go to groserry
        A: #end 
A: #kick @B
A: I believe user B cannot see the chat
A: #end


User
-------------------------------------------------------------------------------

## User
Пользователь
- id - int, pk
- chat_user_id - int, fk to chat user

У нас нет регистрации реального пользователя, поэтому любой аноним который 
оперирует api использует технического User.
Он должен создаваться автоматически при создании таблицы.
Мы пока не рассчитываем что будут другие пользователи 
т.к. используем пока только локально. Сделовательно никакой аутентификации.
Для него же должен создаваться ChatUser.
Пользователь имеет доступ ко всем чатам, т.е. is_super_user = true


Agent
-------------------------------------------------------------------------------

## Agent
Описание агентов, которые импортируються из папки roles.
- id - int, pk
- role - char 128, unique, not null
- chat_user_id - int, fk to chat user
- ... TODO based on current roles

Для каждого Agent должен создаваться ChatUser, где ChatUser.name = Agent.role.
Агент должен реагировать если есть новое сообщение в чате где у него есть доступ.
Agent всегда имеет в контекте текущий чат + один ближний родительский и 
только если он доступен через ChatParticipant,
в моменте когда он должен сформировать ответ.
Должен существовать агент который помогает настроить других агентов для проекта.


Project 
-------------------------------------------------------------------------------

## Project
Проект над которым должны работать агенты.
- id - int, pk
- compose_path - строка с полным путем к compose, unique, can be null

## ProjectChat
Связь между проектами и их корневыми чатами. 
Нужно лишь для группировки, все доступы управляются через ChatParticipant.
- id - int, pk
- project_id
- chat_id

unique togather: project_id - chat_id 


## ProjectAgent
Активные агенты на проекте + донастройка под проект
- id - int, pk
- project_id
- agent_id
- ...
