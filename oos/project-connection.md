# Подключение

Процесс подключения aga к проекту. Переводит проект из «не подключён» в
«подключён»: сканирует кодовую базу, создаёт AGENTS.md, подбирает и
активирует роли агентов.

**Назначение:** автоматизировать первоначальную настройку aga под проект,
чтобы разработчику не нужно было вручную создавать конфиги и разбираться во
внутреннем устройстве фреймворка.

## Состояния
Процесс проходит через следующие состояния (всегда в одном из них):

- **pending** — процесс создан, проект указан, но работа ещё не началась.
- **scanning** — aga изучает кодовую базу проекта: определяет стек,
  инфраструктуру (`docker-compose.yml`, `Dockerfile`, `Cargo.toml`,
  `package.json` и т.д.), наличие/отсутствие `AGENTS.md`.
- **configuring** — на основе сканирования создаётся или подтверждается
  AGENTS.md, формируется черновик конфигурации агентов.
- **activating_agents** — выбранные роли активируются на проекте: каждая
  привязывается к проекту в таблице project_roles.
- **completed** — проект подключён: AGENTS.md на месте, агенты активны.
- **failed** — процесс прерван из-за ошибки (нет доступа к проекту,
  некорректный путь, конфликт конфигов).

## Поведение
- Принимает путь к проекту (локальная файловая система).
- Сканирует проект: ищет файлы-маркеры стека (Cargo.toml → Rust,
  package.json → JS/TS, docker-compose.yml → Docker-инфраструктура,
  requirements.txt → Python, Makefile → generic).
- Если AGENTS.md уже существует — проверяет, не конфликтует ли он с
  настройками aga. Если конфликта нет — оставляет как есть. Если конфликт
  есть — запрашивает решение у разработчика.
- Если AGENTS.md не существует — создаёт его, наполняя на основе сканирования.
- По результатам сканирования составляет список релевантных ролей и
  активирует их:
  - `docker-compose.yml` → docker-helper, app-deployer
  - `Cargo.toml` → rust-ассистент (если такой пресет есть)
  - `package.json` → frontend-assistant / node-helper
  - Неизвестный стек → агент общего назначения
- Если процесс завершился ошибкой — проект остаётся в «не подключён»,
  ошибка логируется.

## Связи
- **Создаёт** AGENTS.md в проекте.
- **Активирует** роли (ProjectRole) на проекте.
- **Меняет состояние** Проекта с «не подключён» на «подключён».

## Вне рамок
- Редактирование существующего AGENTS.md — процесс не переписывает файл, если
  он уже есть и не конфликтует. Разработчик правит его сам.
- Создание новых ролей агентов — процесс только выбирает из существующей
  библиотеки пресетов.
- Деплой и запуск aga-контейнера — процесс только настраивает проект, но не
  запускает aga (это делает разработчик через docker compose up).
