# Участник

Единая учётка участника общения — человека или агента — с правом действовать
в чатах.

## Поля

- **id** — int, pk.
- **name** — 128 chars, not null.
- **kind** — human / agent / anonymous.
- **is_super_user** — bool, default false; доступ ко всем чатам.
- **sso_subject** — can be null; субъект SSO (Keycloak) для человека.
- **role** — can be null; роль агента (для kind = agent).
- **created_at** — когда создана учётка.

## Поведение

- Участник — это человек, агент (бот) или технический аноним.
- **Человек** входит через SSO (Keycloak) и получает доступ к своим сессиям.
- **Агент** создаётся автоматически из роли и получает техническую учётку
  без SSO (`kind = agent`, `role = <имя роли>`, `name = Agent.<role>`).
- **Аноним** — техническая учётка для локальной работы без SSO:
  создаётся автоматически при создании таблицы, `is_super_user = true`.
  Пока аутентификации нет, все локальные запросы ходят под ней.
- Участник отправляет сообщения в чаты — текст и/или файлы.
- Участник может шарить сообщения (в том числе чужие) в чаты, где он участник.
- агентов может быть много и разных; каждый реагирует на новые сообщения
  в чатах, где участвует (см. «Агент-ответ»).

## Связи

- **Является** создателем Чатов.
- **Участвует** в чатах через ChatParticipant.
- **Агенты берутся из** ролей (`roles/`).

## Вне рамок

- Механика входа (Keycloak, OIDC, JWT) — инфраструктура, а не поведение
  этого объекта.
- Формирование ответа агентом — объект «Агент-ответ».
