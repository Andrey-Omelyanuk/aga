# Проект

Проект, к которому подключается aga для работы LLM-агентов. У проекта есть
кодовая база (или её отсутствие — новый проект), путь на диске, а также
настройки интеграции с aga: AGENTS.md и список активных агентов.

## Состояния
- **Не подключён** — проект зарегистрирован в aga (есть запись в БД), но
  интеграция не выполнена: AGENTS.md может отсутствовать, агенты не настроены.
- **Подключён** — aga подключён к проекту: AGENTS.md создан (или подтверждён),
  агенты настроены и активны. Проект готов принимать задачи.
- **Устарел** — проект был подключён, но его структура изменилась (новые
  сервисы в docker-compose, другой стек), и конфигурация агентов может не
  соответствовать текущему состоянию кодовой базы.

## Поведение
- При подключении к aga проект получает AGENTS.md (если отсутствует) и набор
  активных агентов, релевантных его кодовой базе.
- AGENTS.md не перезаписывается без необходимости — если файл уже существует
  и не конфликтует, он сохраняется как есть.
- При повторном подключении проект проверяет актуальность своей конфигурации:
  если кодовая база изменилась (появился/пропал docker-compose.yml, сменился
  стек), он переходит в состояние «Устарел» и требует подтверждения.

## Связи
- **Создаётся через** Подключение — процесс подключения переводит проект из
  «не подключён» в «подключён».
- **Содержит** активных агентов (ProjectRole) — роли, которые работают над
  проектом.
- **Имеет** AGENTS.md — файл с описанием границ и архитектуры проекта для
  агентов.
- **Порождает** Воркстейшны — изолированные копии проекта, где агенты
  выполняют работу.

## Вне рамок
- Создание и редактирование ролей агентов — это зона ответственности
  библиотеки пресетов (`roles/`).
- Запуск задач и трассировка — существующее поведение проекта, не зависит от
  состояния подключения.
