# roles — Agent Role Presets

## Overview
YAML-пресеты ролей агентов. Каждый файл — самостоятельная роль со своим системным промптом, списком разрешённых команд и параметрами LLM.

## Boundaries
- **Делает:** определяет роли (docker-helper, app-deployer и т.д.); задаёт системный промпт; белый список команд (`allowed_commands`); параметры LLM (модель, температура); лимит итераций (`max_iterations`).
- **Не делает:** не содержит исполняемый код или логику; не управляет выполнением; не подгружается runtime автоматически (на момент описания).

## Tech Stack
- YAML 1.1 (формат описания)

## Architecture
```
roles/
├── docker-helper.yml     # Docker-ассистент
├── app-deployer.yml      # Деплоер приложений
└── ...
```

Роли добавляются файлами. Имя файла (без `.yml`) = имя роли.

## Patterns
- **Один файл — одна роль.** Никаких вложенных структур.
- **Имя файла = имя роли.** Соответствует ключу в `Config::roles`.
- **allowed_commands** — белый список базовых команд (без путей и аргументов).
- **max_iterations** — жёсткий лимит; задача прерывается после N шагов LLM.

## Non-Obvious Rules
- `roles/` — библиотека пресетов, а не runtime-директория. Основной конфиг — `config/roles.yaml`, который может компоновать несколько пресетов или переопределять их.
- `prompts/all-agents.md` — общая инструкция для всех агентов (формат `@bash <cmd>`, `@agent:<name>`). Эта инструкция применяется поверх системного промпта конкретной роли.
- Имя роли не обязано совпадать с именем файла после копирования в образ — `Config::load` читает из `config/roles.yaml` по ключам.
- Для тестирования новой роли достаточно добавить файл в `roles/` и включить его в `config/roles.yaml`.

## Verification
- **Валидация:** `config/roles.yaml` должен парситься в `Config` без ошибок — проверяется при старте сервера. Попытка вызвать несуществующую роль возвращает `404 NOT FOUND`.
- **Схема:** каждый пресет проверяется структурой `RoleConfig` (serde). Ошибка схемы — сервер не стартует.
- **Критерий готовности роли:** сервер загружает конфиг; `curl POST /tasks/<rolename>` возвращает `{"status":"ok"}` или `{"status":"waiting_human"}` (не 404).

## Dependencies
- Корневой проект (загружается `Config::load` по пути из `AGA_CONFIG_PATH`).
- LLM API — модель и температура из пресета передаются в `LlmClient`.
