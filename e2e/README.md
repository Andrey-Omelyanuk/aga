# E2E-тесты aga

Единственное место про e2e: что проверяем, на каких данных, как запускать и
почему чего-то здесь нет.

## Зачем и сколько
Логику ядра и фронта проверяют юнит-тесты: `make test` (~240 тестов в
`main/`, SQLite в памяти, моки HTTP/LLM) и `make front-test` (vitest, ~75
тестов моделей и компонентов). Они быстрые и детерминированные, поэтому
основная проверка — в них.

E2E проверяет систему так, как ей пользуется человек: через веб-клиент в
браузере (Playwright). Только так видны стыки, которых нет в юнит-тестах:
- вход через форму Keycloak и токены в SPA;
- websocket Centrifugo в браузере (живые сообщения в чате);
- git-клон в контейнер станции по SSH;
- отдельный процесс `aga agent` и LLM по HTTP.

E2E покрывает то, что делает человек в веб-клиенте: вход и выход, роли,
переписку, нити, работу с агентом. Бизнес-правила здесь не перепроверяются:
если поведение можно проверить юнит-тестом, оно проверяется юнит-тестом, а
e2e-кейс нужен, только когда в нём участвует стык.

## Структура
```text
e2e/
├── README.md                       # этот документ
├── run.sh                          # подготовка стенда + Playwright (make dev-e2e)
├── playwright.config.ts            # baseURL http://dev.localhost, порядок, таймауты
├── tests/
│   ├── login.setup.ts              # вход через Keycloak, сессии alice/bob
│   ├── access.spec.ts              # роли, обновление токена, выход
│   ├── chat.spec.ts                # чат между людьми: живая доставка, ответы, нити, сокращения
│   ├── agent-cycle.spec.ts         # станция, файлы, ответ агента, ask_human, агент в нити
│   └── lib/                        # stand.ts — учётки и API для подготовки; ui.ts — шаги в браузере
├── fixtures/                       # данные, нужные только e2e
│   ├── mock-llm.js                 # детерминированная LLM (ask_human, нити)
│   ├── mock-llm-connection.json    # LLM-подключение к mock
│   └── ask-human-set.json          # набор из одного агента на mock
├── dev-verify.sh                   # стенд поднят (make dev-verify)
└── k8s.sh                          # проверки в кластере (make k8s-verify)
```

## Запуск
| Команда | Где | Что проверяет | Время |
|---|---|---|---|
| `make dev-verify` | dev-стенд (docker compose) | стенд поднят: сервисы, прокси, SSO | ~1 мин |
| `make dev-e2e` | dev-стенд, браузер | 17 кейсов: вход, доступ, чат, рабочий цикл агента | ~1 мин + пересборка |
| `make k8s-verify` | minikube | то, что есть только в k8s: поды, PVC, изоляция | ~10 мин |

```bash
make init        # один раз: .env и main/config/roles.yaml
make dev-up      # поднять dev-стенд
make dev-verify  # стенд жив
make dev-e2e     # пересобрать core/agent/ws-1/ws-2 и прогнать e2e
```

`make dev-e2e` пересоздаёт контейнеры ядра, агент-рантайма и станций (ядро и
рантайм — один образ) и вызывает `e2e/run.sh`. Если менялся только фронт или
тесты, хватит `bash e2e/run.sh`: фронт dev-стенда — vite с HMR. Аргументы
скрипта уходят в `playwright test`, например `bash e2e/run.sh -g "ask_human"`.

Что делает `run.sh`:
1. Ждёт ядро (`401` на `/users`), иначе просит `make dev-up`.
2. Сбрасывает БД сидом, перезапускает `aga agent`, перечитывает прокси (после
   пересоздания контейнеров nginx держит старые IP).
3. Запускает mock-LLM — контейнер `node:22` в сети агент-рантайма.
4. Гоняет Playwright в образе `mcr.microsoft.com/playwright:v1.63.0-noble` с
   `--network host`. На хосте нужны только docker и curl: браузер и
   зависимости — в образе, `node_modules` ставятся в `e2e/` при первом запуске.

Браузер открывает `http://dev.localhost` — тот же адрес, что у человека;
Chromium сам резолвит `*.localhost` в loopback, где слушает прокси стенда.

Нужно: `AGA_SSH_PRIVATE_KEY` в `.env` с доступом к
`git@github.com:Andrey-Omelyanuk/mobx-model-ui.git`; для `k8s-verify` —
kubectl на кластер (minikube) и jq.

## Начальные данные
Два слоя данных.

**Базовый сид** — `aga seed` (`main/src/seed.rs`). Он очищает БД ядра и
создаёт детерминированный набор. Код живёт в ядре, потому что встроен в
бинарь и нужен ещё для демо (`make dev-seed`, `make k8s-seed`). `run.sh`
вызывает его перед каждым прогоном. Что использует e2e:
- Пользователи `alice` (participant) и `bob` (admin). Их `sso_subject`
  совпадают с учётками realm Keycloak (`infra/k8s/core/keycloak-realm.json`),
  пароли — `alice-pass` / `bob-pass`.
- Проект `git@github.com:Andrey-Omelyanuk/mobx-model-ui.git` с набором
  `ui-kit`: агент `ui` привязан к alice и отвечает от её имени.
- LLM-подключение `ollama-local` (`http://ollama:11434/v1`, `qwen3:0.6b`) —
  дефолтное.
- Воркстейшны `ws-1`/`ws-2` в состоянии ready; на `ws-1` открыта сессия alice
  «Сессия: backend».
- «Общий чат» bob и alice без проекта; сокращение `review`.

**Фикстуры e2e** — `e2e/fixtures/`: mock-LLM, подключение к ней и набор из
одного агента — для кейсов `ask_human` и «Агент в нити».

## Тест-кейсы
17 тестов в четырёх файлах. alice и bob работают в отдельных браузерных
контекстах. Тесты ищут элементы по тексту, placeholder и ролям — так, как их
видит человек (см. «Селекторы» ниже).

### Вход — `login.setup.ts`
Запускается первым, остальные зависят от него.

| Кейс | Что проверяет |
|---|---|
| Аноним видит только экран входа | без токена SPA не показывает приложение |
| alice / bob входят через форму Keycloak | SPA → `/auth/login` → форма на `auth.localhost` → токен в SPA; в шапке имя, у bob бейдж `admin` (роль из токена) |

Сессии входа сохраняются в `e2e/.auth/` — остальные тесты стартуют
вошедшими.

### Доступ и сессия входа — `access.spec.ts`
| Кейс | Что проверяет |
|---|---|
| Участник не может отпустить станцию | роль из Keycloak доходит до ядра; UI показывает «Недостаточно прав» |
| Просроченный токен обновляется молча | 401 → `/auth/refresh` ядра → Keycloak → новый токен, экрана входа нет |
| Выход завершает SSO-сессию | «Выйти» → подтверждение Keycloak → экран входа; повторный вход снова спрашивает пароль |

Почему e2e: эти цепочки проходят через браузер, ядро и Keycloak сразу.
Здесь нашлись две ошибки, которых юнит-тесты не видели: Keycloak отклонял
refresh из ядра («Invalid token issuer» — ядро ходит на `keycloak:8080`, а
токены выписаны на `auth.localhost`; исправлено `KC_HOSTNAME` в dev-compose),
и кнопка «Выйти» ничего не делала (метод `me.logout` терял `this`).

### Чат между людьми — `chat.spec.ts`
Место — «Общий чат» сида: без проекта, агенты в нём не отвечают.

| Кейс | Что проверяет |
|---|---|
| Сообщение alice доходит до bob вживую | websocket Centrifugo в браузере; автор и `origin=user` |
| Ответ на сообщение | «↩ ответить» у bob → сообщение у alice |
| Нить | alice начинает нить, bob раскрывает и пишет в неё, alice видит; bob отправляет сообщение «→ в родителя» — у alice копия со ссылкой на нить |
| Сокращение `/review` | сокращение из сида добавляет скрытую заметку, «▸ скрытое» её показывает |

Почему e2e: правила чата и нитей покрыты юнит-тестами ядра, компоненты —
vitest. Здесь — что второй человек видит всё без перезагрузки. Нашлась
ошибка: автор, не состоящий в участниках чата (bob в нити alice),
показывался как `#3`; теперь имя берётся из списка пользователей.

### Рабочий цикл агента — `agent-cycle.spec.ts`
Шаги идут по порядку и продолжают друг друга: сессия из первого шага — чат
для остальных.

| Кейс | Что проверяет |
|---|---|
| Станция | alice закрывает сессию сида, bob отпускает `ws-1`, alice открывает сессию с проектом → чат сессии; занятая станция больше не предлагается |
| Файлы | на «Файлах» у `ws-1` склонированный проект, `README.md` открывается |
| Агент отвечает | bob пишет `@alice что за проект?` — ответ агента от имени alice (`origin=agent`) с артефактом приходит без перезагрузки |
| Без упоминания агент молчит | сообщение без `@alice` — 20 с новых ответов нет |
| Подготовка mock-агента | LLM-подключение к mock — через страницу «LLM»; набор и его привязка к проекту — через API (в UI привязки нет) |
| `ask_human` | вопрос агента — обычное сообщение без служебных строк; bob (не привязан к агенту) отвечает «↩ ответить» — агент заканчивает работу |
| Агент в нити | в нити, начатой alice, сообщение bob без упоминания будит агента alice, ответ — в той же нити |

Цепочка «Агент отвечает»: SPA → HTTP-ядро → Centrifugo → `aga agent` → LLM
(ollama) → команды в станции → ответ в чат → Centrifugo → websocket
браузера. Здесь нашлись две ошибки рантайма, которые юнит-тесты пропускали:
Centrifugo не принимает `?token=` (connect передаётся в `cf_connect`), а канал
в кадре v6 лежит рядом с `pub`, а не внутри него.

Ответ ollama недетерминирован, поэтому проверяется только факт ответа.
Дальше агент работает на mock-LLM (`fixtures/mock-llm.js`): ответ зависит от
последнего сообщения — «выкати прод» вызывает `ask_human`, остальное получает
«Готово (e2e mock): <текст>». Так `ask_human` и нити проверяются точно.

### Селекторы
Где текста мало, во фронте стоят `data-testid`:
- `message` — строка сообщения, с атрибутами `data-message-id`,
  `data-author`, `data-origin`;
- `artifact` — артефакт сообщения.

Переименовал кнопку или placeholder — поправь e2e.

## dev-verify: стенд поднят
Скрипт — `e2e/dev-verify.sh`, без браузера. Только «всё отвечает»:
- Keycloak realm `aga`; ядро отклоняет анонима (`401`), `/auth/login`
  редиректит (`307`).
- В `ws-1`/`ws-2` есть git-репозиторий `/work/project`.
- В ollama загружена `qwen3:0.6b`.
- Фронт отвечает на `${AGA_FRONT_PORT:-8081}`; прокси раздаёт
  `dev.localhost`, `api.localhost`, `auth.localhost`.

## k8s-verify: только то, что есть в кластере
Скрипт — `e2e/k8s.sh`, без браузера: проверяется инфраструктура, а не путь
пользователя (он одинаков на обоих стендах). LLM не нужен. Скрипт сам
собирает и загружает образы, деплоит стенд и форвардит порты ядра (18080),
Keycloak (18081) и фронта (18082). После проверки стенд остаётся поднятым.

- Ядро и фронт — деплойменты в кластере, API и SPA отвечают, CORS пускает
  origin фронта.
- Keycloak в кластере: страница входа доступна извне, `/auth/login`
  редиректит на неё; невалидный токен получает `401`.
- Воркстейшн — отдельный под `ws-<id>` с копией проекта, своим Docker и своей
  веткой; у пода нет доступа к API кластера.
- Команды агента идут из пода ядра в под станции (`kubectl exec`).
- Удаление станции удаляет под; данные ядра переживают рестарт (PVC).

## Что e2e сознательно не проверяет
- **Бизнес-правила чата, наборов, LLM-подключений, скиллов и сокращений** —
  юнит-тесты `server.rs`, `chat.rs`, `trace.rs`.
- **Страницы настройки** (Config: скиллы, сокращения, наборы, LLM, MCP) —
  это формы поверх CRUD, покрыты vitest и тестами API.
- **Качество ответов LLM.** Это не свойство платформы.
- **MCP-серверы.** Протокол и вызовы покрыты `mcp.rs`; сквозного сценария нет.
- **Песочница территории** (запись вне своей папки падает). Её проверяет
  юнит-тест ядра в настоящем контейнере станции:
  `sandbox_in_workstation_blocks_writes_outside_territory` в `scope.rs`. Он
  помечен `#[ignore]`, потому что нужен docker и образ `aga-workstation:dev`;
  запуск — `cargo test -- --ignored sandbox_in_workstation` в `main/`.

## Известные пробелы
- **Привязка набора агентов к проекту** есть только в API, поэтому в
  `agent-cycle.spec.ts` это шаг подготовки. Появится в UI — перевести на UI.
- **Выход без `id_token_hint`.** Ядро не передаёт его в Keycloak, поэтому
  Keycloak просит подтвердить выход отдельной страницей. Тест проходит её, как
  человек; убрать шаг можно, если хранить id_token.
- **k8s-стенд и refresh.** В `infra/k8s/core/50-deployment-keycloak.yaml` нет
  фиксированного `KC_HOSTNAME`, как в dev-compose, — тихое обновление токена
  там, вероятно, сломано так же. Проверить на кластере.
- **Внешняя зависимость.** `agent-cycle.spec.ts` клонирует репозиторий с
  GitHub. Без сети или без SSH-доступа он падает.

## Если упало
- Отчёт: `e2e/playwright-report/` (HTML). У упавшего теста — trace, скриншот
  и видео в `e2e/test-results/`. Открыть: `cd e2e && npx playwright show-report`
  или `npx playwright show-trace test-results/<тест>/trace.zip`.
- Ответа агента нет — смотри `docker logs aga-agent`. Цикл
  `подписка завершена, переподключение` каждые пару секунд означает, что
  рантайм не подключается к Centrifugo (`docker logs aga-centrifugo`).
  Плановое переподключение раз в 30 секунд — норма.
- Сообщения не появляются без перезагрузки — websocket браузера не
  подключился к `pub-sub.localhost` (консоль браузера в trace).
- `README.md` не появился на «Файлах» — нет SSH-доступа к GitHub из станции
  (`AGA_SSH_PRIVATE_KEY` в `.env`).
- Рантайм и ядро — один образ `aga-core:dev`. При ручном запуске
  `e2e/run.sh` после правок ядра пересобери оба (`make dev-e2e` делает это
  сам), иначе рантайм останется старым.
