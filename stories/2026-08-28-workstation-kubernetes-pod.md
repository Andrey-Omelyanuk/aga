# Воркстейшн как под в Kubernetes

Нужно много параллельных изолированных воркстейшнов — отдельных машин
разработчика, где агент работает над проектом. Сейчас воркстейшн — запись
в БД, команды уходят на хост через docker.sock, изоляции нет. Масштабируем
через Kubernetes: воркстейшн — это под, внутри которого свой Docker
(включая docker compose) и git-копия проекта. Для агента под выглядит
обычной dev-машиной и не знает про кластер; кластером управляет только ядро.
Что считать результатом — решают правила самого проекта. Кластер агенту
не отдаём — внутри воркстейшна только git и Docker, доступа к k8s API нет.

## Поведение
- созданный воркстейшн поднимает отдельный под с git-копией проекта и собственным Docker
- команды агента воркстейшна выполняются внутри его пода
- удалённый воркстейшн исчезает из списка, его под удалён
- проект регистрируется git-URL, а не compose_path
- воркстейшн работает на своей git-ветке
- сервисы, поднятые воркстейшном, не пересекаются с сервисами других воркстейшнов
- агент внутри воркстейшна не имеет доступа к k8s API кластера
- локальный запуск поднимает воркстейшны в локальном кластере (minikube и подобные)
