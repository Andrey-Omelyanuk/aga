# Дефолтная LLM выбирается на странице «LLM», в dev-стенде маленькая LLM

Сейчас агент без выбранного подключения работает на дефолтной LLM из env ядра
(LLM_API_URL, LLM_API_KEY, LLM_MODEL) — поменять её можно только перезапуском
ядра с другими переменными. Хочу убрать дефолт через env совсем, а дефолтную
LLM выбирать на странице «LLM»: у каждого подключения к LLM своя модель, и одно
из подключений отмечается дефолтным — агенты без своего подключения ходят к нему.
Для разработки поднимаем контейнер с маленькой LLM прямо в dev-стенде: при
make dev-up он стартует, подключение к нему создаётся и ставится дефолтным само.
Интеллект модели не важен — главное проверить, что цикл запускается, поэтому
модель берём самую маленькую (до 1B).

## Поведение
- при `make dev-up` в dev-стенде поднимается контейнер с маленькой LLM (модель до 1B)
- после подъёма dev-стенда на странице «LLM» уже есть подключение к этому контейнеру, и оно отмечено как дефолтное
- создание и правка подключения задают имя, url, ключ и модель
- на странице «LLM» одно из подключений отмечается дефолтным, и выбор можно снять
- агент набора без выбранного подключения ходит к дефолтной LLM: url, ключ и модель из отмеченного подключения
- у агента набора со своим подключением дефолтная LLM не влияет
- если дефолтная LLM не выбрана (или выбранную удалили), запуск агента без подключения не проходит — LLM нет
- удаление подключения, отмеченного дефолтным, разрешено: оно исчезает из списка, а дефолт сбрасывается в «не выбран»
- ядро не ходит к LLM из env: переменные LLM_API_URL, LLM_API_KEY и LLM_MODEL не используются ни в dev-стенде, ни в k8s-стенде
