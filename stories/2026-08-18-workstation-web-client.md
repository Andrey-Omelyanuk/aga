# Рабочие станции (Workstations) и веб-клиент с SSO

**Источник:** `/story` — голос пользователя

## Что хочет разработчик

Платформа, где LLM-агенты работают над проектами в изолированных
рабочих станциях (workstations), а разработчики управляют всем через
веб-клиент. Приложение — веб-сервис, поднимается целиком через Docker
и крутится на мощном сервере; пользователи работают через браузер.

## Концепция воркстейшна

- Воркстейшн — отдельный Docker-контейнер с собственной копией проекта,
  в которой агент выполняет работу.
- Внутри воркстейшна можно поднимать свой Docker (**DinD** — Docker-in-Docker,
  отдельный демон на каждый воркстейшн). Это даёт полную изоляцию портов:
  у каждого воркстейшна свой bridge-неймспейс, каждый поднимает свои
  сервисы, наружу они не публикуются.
- Воркстейшнов может быть много, их работа не пересекается (порты
  контейнеров, сети, ресурсы).
- Код изолируется через ветки в git: каждый воркстейшн работает на своей
  ветке, результат — через PR.

## Сессия и коллаборация

- На одном воркстейшне может быть только **1 активная сессия** (один
  активный запуск агента в единицу времени).
- Но в чат-сессию воркстейшна может быть подключено **много пользователей** —
  это совместная разработка: все видят один и тот же вывод агента,
  команды идут в общую очередь.
- Команды от людей идут в ту же очередь, что и команды агента
  (сериализация на воркстейшн).

## Веб-клиент

- Сложный веб-клиент: терминал, редактор/дерево файлов, git-панель
  (commit/push/PR), окно чата — всё в браузере, стримом к воркстейшну
  (SSE/WebSocket).
- Веб-клиент подключается к REST API сервиса aga.
- Локального Docker у пользователей нет — всё на сервере.

## Аутентификация (Keycloak)

- **Keycloak — отдельный сервис** в обвязке, отвечает за аутентификацию
  (и, возможно, авторизацию) для API-сервиса aga.
- SSO: веб-клиент входит через Keycloak, API валидирует JWT.
- OIDC-интеграция: discovery, auth-code flow для веб-клиента, проверка
  JWT (JWKS) для API.
- Keycloak поднимается как отдельный сервис в docker-compose.

## Пользователи и боты (ChatUser)

- **ChatUser совмещает реальных пользователей и ботов.**
- Реальные пользователи — через SSO (Keycloak), с ролями и доступами.
- Боты — агенты из `roles/`, их тоже может быть много и разных;
  у них технические ChatUser, вход через SSO не нужен.
- Единая модель участников чата: и человек, и агент — это ChatUser.

## Что НЕ входит в историю

- Детали реализации DinD (Sysbox/rootless, ingress) — решаются в процессе.
- Конкретный механизм авторизации в Keycloak (роли/скоупы) — уточняется.
- Миграция старых API/структур — старые границы в расчёт не берутся,
  приоритет — текущая концепция.
