# E2E: рабочий цикл агента на проекте mobx-model-ui

Нужна e2e-проверка всего рабочего цикла на dev-стенде: берём занятый
воркстейшн, закрываем его сессию (владелец), отпускаем станцию, переключаем её
на реальный проект mobx-model-ui и открываем сессию, где просто спрашиваем
агента, что это за проект. Цепочка живая: HTTP API через SSO (роли участника и
суперпользователя), код проекта в воркстейшн попадает git-клоном
git@github.com:Andrey-Omelyanuk/mobx-model-ui.git (нужен SSH-доступ
AGA_SSH_PRIVATE_KEY), агент отвечает через маленькую LLM dev-стенда. Качество
ответа не проверяем — модель слабая, главное, что цикл запускается и агент
отвечает непустым текстом. Сценарий стартует с чистого сида (dev-seed), чтобы
состояние было детерминировано.

## Поведение
- закрытая владельцем сессия освобождает занятый воркстейшн, и на нём снова можно переключить проект
- отпущенный воркстейшн переключается на проект mobx-model-ui, и в `/work/project` воркстейшна появляется код проекта
- на свободном воркстейшне с проектом mobx-model-ui открывается сессия
- сообщение «@Agent.ui: что за проект?» в сессии получает непустой ответ агента, и в чате появляется артефакт с этим ответом
- `make dev-e2e` на dev-стенде прогоняет весь сценарий (с чистым сидом) и завершается успехом

Что сознательно не делаем: качество ответа не проверяем (хватает непустого
ответа), k8s-стенд сценарий не трогает, unit-тесты не заменяет.
