# Подключения к LLM и выбор их в наборе агентов

Сейчас агенты ходят к одной LLM из env ядра (url, ключ, дефолтная модель) —
для разных задач нужен доступ к разным LLM, а настраивается это только
перезапуском ядра с другими переменными. Хочу отдельную настройку: подключение
к LLM — название, url к API и ключ доступа — создаётся один раз, живёт в БД, а
у каждого агента набора (AgentSet) выбирается одно из созданных подключений. В
веб-клиенте рядом с «Agent Set» появляется страница «LLM» со списком
подключений. Агент без выбранного подключения работает на дефолтной LLM из env,
как раньше. Свою модель и температуру у агента набора не задаём — только выбор
подключения, модель общая. Ключ показываем как есть, маскировки нет; дефолтное
подключение из env при старте не создаём.

## Поведение
- созданное подключение к LLM (название, url API, ключ) видно в списке на странице «LLM»
- у агента набора в редакторе выбирается одно из созданных подключений; своей модели и температуры у агента больше нет
- агент набора, запущенный задачей или `@Agent.<имя>`, ходит к LLM по url и ключу выбранного подключения
- агент без выбранного подключения работает на дефолтной LLM из env, как раньше
- разные агенты одного набора ходят к разным подключениям
- правка подключения меняет url и ключ для всех использующих его агентов без их перенастройки
- удалённое подключение исчезает из списка, а агенты, его использовавшие, остаются без подключения и работают на дефолтной LLM из env
