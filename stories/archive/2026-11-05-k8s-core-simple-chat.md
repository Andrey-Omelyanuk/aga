# Ядро в k8s и простой чат

Передумал делать сложное приложение. Внешний админ — не пользователь aga, у
него полный доступ к хостам и кластеру: он ставит aga в k8s, выдаёт ей
ограниченные права, задаёт политику кластера и подключение к LLM (env при
запуске aga), заводит учётки и роли в SSO; какую модель дать — его забота,
слабые модели мы берём только для тестов стенда. Провайдера LLM считаем своим:
секреты из чата и вывод команд уходят модели, ввода секретов в обход неё пока
нет. Сама aga — ядро, где всё исполняется, и максимально простой интерфейс:
проекты и чат с нейронкой.

Проект — git-репозиторий. Каждый чат проекта — свой инстанс проекта в своём
namespace: свой клон, своя ветка, своё окружение, поэтому чаты друг другу не
мешают, а работа разных чатов сходится только через git. Без дела инстанс
засыпает, чтобы десятки чатов не держали ресурсы. Закрытие чата сначала пушит
его ветку — незапушенная работа не теряется. Нет места для инстанса — новый чат
не открыть, пока что-то не закрыто. docker compose не используем ни для
проектов, ни для стенда.

Роли из SSO: участник работает с проектами, мейнтейнер ещё и пересобирает
приложение (отдельная история). Всё прочее, что есть сейчас — наборы агентов и
территории, пул воркстейшнов и сессии, нити, сокращения, агенты от имени
пользователя, подключения к LLM в БД, страницы файлов, Changes, LLM, MCP и
справки, — из продукта уходит; понадобится — мейнтейнер попросит нейронку
собрать это в новом варианте приложения.

## Поведение
- при старте ядро называет недостающие права в k8s и отсутствующую политику кластера
- после входа пользователь видит один экран: список проектов и чат выбранного проекта
- у проекта несколько чатов
- каждый чат проекта работает в своём инстансе проекта
- у каждого инстанса свой namespace
- ядро не может создать или удалить namespace вне своего префикса — кластер отклоняет запрос
- на сообщение пользователя в чате проекта нейронка отвечает без упоминания `@`
- сообщения одного чата нейронка обрабатывает по очереди
- первое сообщение в чате поднимает его инстанс с клоном репозитория
- инстанс работает в своей ветке репозитория
- правки одного инстанса не видны в другом, пока не прошли через git
- команды нейронки в чате выполняются в поде его инстанса
- файлы инстанса переживают перезапуск его пода
- инстанс чата без активности дольше заданного в env времени (по умолчанию 30 минут) засыпает: поды останавливаются, файлы остаются
- сообщение в уснувший чат будит его инстанс
- закрытие чата удаляет его инстанс
- закрытие чата сначала пушит ветку его инстанса в репозиторий
- если пуш не прошёл, чат не закрывается и пользователь видит причину
- закрыть чат может его автор или мейнтейнер
- когда инстанс негде развернуть — исчерпан предел бодрствующих инстансов из env или кластер не принимает под, — новый чат не открывается
- отказ в новом чате предлагает пользователю закрыть один из его чатов
- когда уснувший чат негде разбудить, пользователь видит это и предложение закрыть один из его чатов
- команды нейронки имеют доступ к k8s API только в namespace своего инстанса
- инстанс не видит сеть и секреты других инстансов и ядра
- namespace инстанса получает квоту и уровень безопасности подов из политики внешнего админа
- приложение не может ослабить квоту или уровень безопасности подов своего namespace
- удаление проекта удаляет namespace всех его инстансов
- удалить проект может только мейнтейнер
- удаление проекта сначала пушит ветки всех его инстансов
- если пуш хоть одной ветки не прошёл, проект не удаляется и мейнтейнер видит причину
- проект без своего ключа ходит в git общим ключом aga из env
- участник создаёт проекту свой ключ в интерфейсе проекта
- у проекта со своим ключом видна публичная часть ключа
- проект со своим ключом ходит в git только им: общего ключа в namespace его инстансов нет
- приватная часть ключа проекта не показывается в интерфейсе
- нейронка отвечает моделью из env, который внешний админ задал при запуске aga
- без LLM в env чат сообщает, что LLM не настроена
- стенд разработки и e2e поднимается только в k8s
