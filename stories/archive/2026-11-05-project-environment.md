# Окружение проекта в k8s

Docker внутри пода инстанса нет, и привилегий у инстанса нет. Окружение,
которое раньше поднимал docker compose, нейронка переносит в namespace
инстанса: сервисы — под теми же именами, что в compose, поэтому конфиги
проекта не меняются. Тестам, которым нужен Docker API (testcontainers), его
даёт kubedock — контейнеры становятся подами инстанса. Окружение поднимается
только через Deployment или StatefulSet: голые поды сон инстанса не переживают.

Образы собираются по обычным Dockerfile на общем сборщике BuildKit, который
внешний админ ставит в отдельный namespace со своими привилегиями, и
публикуются в registry, который тоже даёт админ; адреса обоих — в env. Образы
общие для всех инстансов проекта. Кэш сборщика общий на все проекты — это
принимаем. Тесты, которым нужен настоящий Docker (privileged, Docker внутри
Docker), — не забота aga.

## Поведение
- под инстанса обращается к сервису окружения по имени из docker compose
- сервисы окружения живут в namespace инстанса
- окружение, поднятое через Deployment или StatefulSet, восстанавливается после пробуждения инстанса
- тест на testcontainers в поде инстанса запускает свои контейнеры подами в namespace инстанса
- контейнеры теста удаляются после теста
- нейронка собирает образ проекта по его Dockerfile на сборщике из env
- сборка образа не требует привилегий у пода инстанса
- собранный образ публикуется в registry из env под префиксом проекта
- под в namespace инстанса запускается из образа, собранного в его проекте
- без сборщика в env сборка образа сообщает, что сборщик не задан
- без registry в env сборка образа сообщает, что registry не задан
