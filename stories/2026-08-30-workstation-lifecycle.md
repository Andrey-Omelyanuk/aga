# Жизненный цикл рабочей станции

Рабочая станция (ws) живёт полным циклом: поднимается, работает над проектом,
выключается админом. В k8s это под, в docker compose — отдельный сервис.
Мне нужно, чтобы станция брала на себя рутину: при подъёме она монтирует
секреты для сторонних CLI (ssh-ключ, ключи авторизации), а когда надо — может
работать с другим проектом, не требуя пересоздания. Выключение — процедура
админа в k8s: станция удаляется, ресурсы чистятся. Падение станции не страшно:
если ws упал, в БД это отражается; восстановление прогресса — ручное, через
UI: на свободном ws открывают сессию, она распознаёт, что продолжает
прерванную сессию с упавшей станции, и восстанавливает её ход.

## Поведение
- подъём воркстейшна монтирует в ws секрет из кластера, названный суперпользователем при создании
- переключить ws на другой проект нельзя, пока на ней есть открытая сессия
- после переключения ws содержит код нового проекта: её каталог `/work/project` перезаписан, и сам ws (под/сервис) не пересоздаётся
- упавший ws в БД отмечен как недоступный
- открытая на свободном ws сессия распознаёт продолжение прерванной сессии с упавшей станции и восстанавливает её: файлы, изменённые LLM, снова на диске, история доступна
- открыть новую сессию на упавшем ws нельзя
- открытая сессия без падения станции никого не продолжает
